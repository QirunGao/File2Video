# 架构文档与代码差异汇总（vNext-7 对照）

更新时间：2026-02-25  
对照文档：`docs/项目整理说明.md`（vNext-7 架构说明）

## 1. 结论（摘要）

当前代码已经实现了 vNext-7 的主线思路：

- Headerless 顺序时基（按槽位顺序推进 `t`）
- 槽位内恒定 `sys/par` 分割（Constant Split）
- 两态门控（坏槽位擦除化）
- 元数据前缀强化（`repeat(META, r_meta)`）
- 基于窗口参数的软解码流程（但 FEC 不是文档中的 QC-SC-RA）

但与架构文档相比，仍有明显差异，主要集中在：

- FEC 实现仍为简化 RA-like，而非 `Systematic QC-SC-RA`
- I/O 路径仍是 `raw YUV420p`，未接入 `ffmpeg/x264` 的 `mp4` 管道
- `heavy_geom` 目前仅增强为块级平移搜索，未实现缩放/更重几何估计
- 译码会话仍是“全量恢复后一次性写文件”，未实现文档描述的块级写回/窗口状态回收

## 3. 与文档差异汇总（按优先级）

### P0（架构级差异，影响“是否真正符合 vNext-7 目标”）

1. FEC 不是文档定义的 `Systematic QC-SC-RA`
2. 译码器不是 QC/SC 稀疏图窗口 BP/Min-Sum/Layered
3. Session 未实现块级写回与窗口状态回收

### P1（工程能力差异，影响完整使用场景）

1. 仍未接入 `ffmpeg/x264` / `mp4` 管道（当前为 raw YUV420p）
2. `heavy_geom` 仅块级平移搜索，未含缩放/更复杂几何
3. `session` 仍未实现块级 CRC（仅作为可选早停/定位机制，文档中提及）

### P2（可选增强 / 文档扩展项）

1. 未实现“同步锚点帧”（第 18 节，可选）
2. 未实现更丰富的 `Q` 特征与门控策略调优
3. 测试集尚未覆盖文档第 15 节的完整矩阵（特别是压缩链路与大量统计回归）

## 4. 当前代码已具备的良好基础（继续演进的支点）

- 模块分层已接近文档目标：`phy_channel / mapper / fec / session`
- Constant Split 已稳定落地，可作为后续替换 FEC 的固定接口层
- Headerless 顺序时基已经成形，整帧擦除语义明确
- `heavy_geom` 入口与测试已具备，便于继续扩展几何模型
- Profile 机制已存在，适合继续塞入 FEC 参数（`Z/m/q/...`）

## 5. 建议下一步（按落地成本排序）

1. 在保持当前接口不变前提下，让 FEC 真正消费 profile 中的 `qc_z / sc_memory / ra_repeat` 参数（先做参数驱动的 RA，再演进到 QC-SC-RA）
2. 将 `session` 改为块级输出模型（即使 FEC 仍简化，也能先完成流水线形态）
3. 接入 `ffmpeg/x264` 管道，保留 raw YUV 作为调试后门
4. 扩展 `heavy_geom` 到平移+缩放（逐步接近文档约束）
5. 如需早停/定位优化，再补块级 CRC（保持不进入对外协议）
