# File2VideoEncoder v1.2.2-r3f 单文件规范（固定实现版：最优正规形；工程优化/简化；不改变协议语义）

本规范用于实现 File2VideoEncoder 解码端（Rust 优先）及其必要的生成器产物（表/常量）。编码端“文件→帧→FFmpeg 压缩封装”不在此文档展开（仅需遵守同一帧型与 payload 规则即可）。

目标：给出一份可直接开工落地的、**不依赖“略/见旧版本”** 的单文件工程规范。  
注意：部分“固定布局/固定 QC 结构”等虽然在协议中是常量，但其具体数值（区域坐标表、QC 连接表、π/π⁻¹、route_packed 等）通常由生成器产出并固化为 Rust const 或二进制 blob；本规范明确它们的格式、校验规则与运行期使用方式，从而实现“单文件可落地”。

---

## 0. 版本与不变量

### 0.1 版本标识
- 规范版本：`v1.2.2-r3f`
- 协议语义：与 `v1.2.2-r3` 保持一致（仅工程实现固定化/最优化，不改变协议语义与输出定义）
- 允许的差异：仅限“内存布局、循环形态、默认开关、表派生方式、确定性规则收紧、性能优化路径固定”

### 0.2 固定立场（不可选，必须遵守）
- 交织 `π` 强制启用（profile 固化置换与逆置换）
- 不使用块 CRC（译码早停仅 syndrome；正确性最终由文件 hash 判定）
- 门控阈值完全由 profile 固定，不提供覆盖开关
- 无槽级门控（只做帧级两态）
- 无近阈值降权/clip（只有“保留/擦除”两态）
- Anchor 必须存在且硬规格化：携带可判别 `anchor_id (mod M_anchor)`，并提供确定性的时基校准规则
- 所有视频输入/输出必须通过 FFmpeg；核心只处理 `rawvideo(YUV420p)` 帧流
- 同输入必须产生同输出（逐元素一致）：禁止非确定性并行归约；任何并行仅限互不影响的候选评分；汇总必须确定性

### 0.3 可选工程策略（不改变协议语义）
- `--heavy-geom`：重几何搜索（冷路径）
- `--anchor-prune`：Anchor 候选剪枝（默认关闭；必须可证明不改变 argmax；debug 需断言/校验）
- `--no-route-seqwrite`：关闭默认顺序写（仅回归/调试）
- `--no-pix-off`：关闭 pix_off 派生（仅回归/调试）
- `--materialize-erase`：擦除 span 物化写 0 到 ring（默认关闭；需基准证据 + 回归一致）

## 1. 一句话流水线（解码端）

**FFmpeg 解压 → raw YUV420p 帧 → 帧同步/标定 → Anchor 检测与校准 → 帧级两态门控（擦除=逻辑空洞） →（非擦除帧）槽位 LLR 提取（每帧 LUT）→ pix_off 顺序写入 sys/par ring（每槽位一次取模，最多两段连续写，段内 0 bounds check）→ QC-SC-RA 窗口 Layered 软译码（R-only，Lq delta 更新，sat_i16，syndrome 增量早停）→ chunk 写回 → 最终 hash 校验**

## 2. 术语与类型

### 2.1 术语
- frame：视频帧（raw YUV420p）
- slot：帧内 payload 槽位（固定数量 `slots_per_frame=24`）
- coded bit：槽位 payload 中的编码比特（总数 `B=4096`）
- LLR：软信息，int16 饱和
- SYS / PAR：systematic 段与 parity 段（Constant Split）
- chunk：文件分块组织单位（由 sys 槽位累计形成边界）
- window：译码滑窗（chunk 维度）
- π：槽位内交织置换（长度 4096）
- route：coded bit →（SYS/PAR，offset）映射
- pix_off：coded bit（或最终写入位置）→ Y 平面像素偏移映射
- erased：门控判定为擦除的接收帧（逻辑空洞，LLR=0）

### 2.2 基本类型（Rust 建议）
- `LLR = i16`
- `Pix = u8`（Y 平面像素）
- `PixOff = u32`（Y 平面 byte offset 或 index；4K/8K 足够）
- 所有中间累积：`i32`/`i64`（显式 clamp，不依赖溢出行为）

### 2.3 饱和算术（唯一真理）
定义 `sat_i16(x: i32) -> i16`：
- 输出范围：`[-llr_sat, +llr_sat]`，其中 `llr_sat=12000`
- 规则：
   - `if x > +llr_sat: +llr_sat`
   - `if x < -llr_sat: -llr_sat`
   - else `x as i16`
     SIMD 实现必须逐元素等价于该标量参考。

## 3. 全局常量与 profile 参数

### 3.1 全局常量（所有 profile 相同）
- `B = 4096`（槽位 coded bits）
- `Z = 128`（QC lifting，2 的幂）
- `slots_per_frame = 24`
- `N_anchor_frames = 12`（每隔 12 帧写 Anchor）
- LLR：
   - `llr_scale_q = 4096`（Q12，仅 LUT 构建时使用）
   - `llr_sat = 12000`
- META：
   - `K_meta_chunks = 8`（前 8 个 chunk 强化）
- Anchor：
   - `M_anchor = 127`
   - `L_anchor = 127`
   - `R_anchor_blocks = 8`
   - `T_anchor_hit = 650`
   - `T_anchor_margin = 100`
   - `K_anchor_jump_max = 8`

- 冗余比 `r = B_par / B_sys`

- 门控阈值 `T_frame_drop` 为 Q15（0..32767）

### 3.3 启动期 profile 校验（必须）
1) `B_sys % Z == 0` 且 `B_par % Z == 0`
2) `B_sys + B_par == 4096`
3) `chunk_bits = N_sys_slots_per_chunk * B_sys` 为 8 的倍数
4) 若编入 `PI`：π 长度为 `B`，且与槽位 bit 提取顺序一致（见 6）
5) 若编入 `ROUTE_PACKED`：`route_packed.len == B`，offset 域 `<=4095`，sel 域为 0/1
6) 生成器输出的 QC shift（`EDGE_SHIFT` 或可选 `EDGE_SHIFT_PARAM` 中的 shift 语义）必须在 `0..127`；超界视为生成器 bug（启动期拒绝）

## 4. 生成器产物（固定格式；运行期依赖；单文件定义）

为实现“单文件可落地”，本规范把所有“固定但巨大”的常量（布局表、QC 连接、π、route 等）归类为生成器产物。实现者可选择：
- 方案 A：生成 Rust `const`（推荐：零解析、强确定性）
- 方案 B：生成二进制 blob + 启动期一次校验加载（必须固定端序、对齐、版本与校验策略）

### 4.0 编译分层（r3f 推荐；低风险优化）
- `release` 默认采用“运行时最小集”：
   - 保留热路径必需表：`SYS_PIX_OFF / PAR_PIX_OFF`（以及 `FRAME_LAYOUT`、QC 表、Anchor 表）
   - 不要求编入 `PI / ROUTE_PACKED / PIX_OFF_ALL`（以及仅用于其校验/回退的辅助表）
- `debug` 或 `cfg(feature="regression")` 编入“回归/校验扩展集”：
   - 用于启动期强校验、`--no-route-seqwrite` / `--no-pix-off` 回退路径、单测对照
- 若采用 release 最小集：相关强校验应转移到生成器离线校验或 debug/regression 构建执行，语义不变。
- 回退/校验实现建议隔离到独立模块（如 `mod regression`）并受 feature gate 控制；`release` 默认不链接回退路径代码。
- 若采用 blob 方案，必须写死：
   - 端序（推荐 LE）
   - 各表元素对齐（如 `u32` 至少 4B 对齐）
   - blob 版本号（与规范/生成器版本绑定）
   - blob 校验（长度 + 校验和/哈希）用于启动期拒绝错误产物

### 4.1 产物清单（必须）
对每个 profile（或全局共享）生成以下对象（生成器可输出全量；运行时可按 4.0 分层编入）：

A) 帧布局（全局共享）
- `FRAME_LAYOUT_V1`: 描述 locator/pilots/anchor/slots 在帧内的固定区域与采样规则（见 5）

B) 交织与映射（每个 profile）
- `PI[4096] : u16`（置换，值域 0..4095，必须为全排列；推荐作为回归/校验表编入 debug/regression）
- `PI_INV[4096] : u16`（逆置换；**可选产物**。推荐由 `PI` 启动期一次构建，仅用于校验/回退）
- `ROUTE_PACKED[4096] : u16`：`bit15=sel`（0=sys,1=par），`bit0..11=off`（0..4095）（回归/校验用表，推荐仅 debug/regression 编入）
- `PIX_OFF_ALL[4096] : u32`（推荐生成器直接生成；否则运行期派生，见 7；回归/校验用表，推荐仅 debug/regression 编入）

C) “最优正规形”写入表（每个 profile，推荐必须生成）
- `SYS_PIX_OFF[B_sys] : u32`
- `PAR_PIX_OFF[B_par] : u32`  
  说明：这两表是 demod→ring 热路径的最终输入，也是 `release` 最小集优先保留的映射表。若你只生成 `PIX_OFF_ALL + ROUTE_PACKED`，运行期必须派生这两表，并通过校验（见 7.3）。

D) QC 连接（每个 profile，必须）
- SoA、layer 连续布局：
   - `LAYER_EDGE_START[L+1] : u32`（包含终止）
   - `EDGE_VAR_IDX[E] : u16/u32`（若 var_count<65536 则 u16，否则 u32）
   - `EDGE_SHIFT[E] : u8`（默认；取值 0..127，热路径无分支算出两段拼接，见 13）
   - `EDGE_SHIFT_PARAM[E] : Shift2Seg`（可选扩展；仅在需要“非标准两段”表示时保留，见 13）
   - `EDGE_CHECK_ID[E] : u16/u32`（可选；仅在使用 `VAR_TO_EDGES` 做 syndrome/hard-bit 更新或其他 edge 级增量逻辑时需要；若 `CHECK_COUNT < 65536` 优先 `u16`）
- 以及：
   - `VAR_COUNT`, `CHECK_COUNT`, `EDGE_COUNT`
   - `VAR_CHECK_START[VAR_COUNT+1] : u32` + `VAR_CHECK_ID[*] : u32`（推荐默认，用于 syndrome 翻转增量；按升序、去重，见 12.8）
   - `VAR_TO_EDGES`（可选；仅当还需要 edge id 做别的增量逻辑时保留）

E) Anchor 序列（全局共享或按版本固定）
- `ANCHOR_SEQ[L_anchor] : i8`（或 u8 映射到 ±1）
- `ANCHOR_BLOCK_REPEAT = R_anchor_blocks`（必须为 8）
- 以及 anchor 采样规则（在 FRAME_LAYOUT 中定义）

### 4.2 产物校验（启动期必须）
- 若编入 `PI`：校验全排列；若同时编入 `PI_INV`，则校验 `PI_INV[PI[i]]=i`；若未编入 `PI_INV`，可在 debug/regression 启动期由 `PI` 一次构建后校验
- 若编入 `ROUTE_PACKED`：校验 sel∈{0,1}；off 在范围；并且 sys 侧 off 覆盖 `0..B_sys-1` 一次且仅一次；par 侧 off 覆盖 `0..B_par-1` 一次且仅一次
- 若同时编入 `ROUTE_PACKED + PIX_OFF_ALL`：校验 `SYS_PIX_OFF/PAR_PIX_OFF` 与其关系（见 7.3）
- QC：`EDGE_SHIFT`（或 `EDGE_SHIFT_PARAM`）必须等价于 Z=128 循环移位；所有索引不越界；layer 区间单调；E 总数一致
- 若使用 `VAR_CHECK_START/VAR_CHECK_ID`：每个变量邻接 check 列表必须有序、去重且不越界
- Anchor：序列长度与取值域；阈值常量一致
- 在分辨率与帧布局确定后，必须校验 `SYS_PIX_OFF/PAR_PIX_OFF`（以及任何 `PIX_OFF_ALL`）的最大偏移 `< y_plane_len`
- 说明：采用 4.0 的 `release` 最小集时，未编入表的强校验应在生成器离线流程或 debug/regression 构建完成。
- 校验分层建议：启动期做强校验；运行期仅在 debug/regression 下保留轻断言（例如 spot-check）；release 不在热路径重复校验

## 5. 帧型与采样（raw YUV420p；固定布局由 FRAME_LAYOUT 定义）

### 5.1 输入帧格式（必须）
- 只接受 FFmpeg 输出的 `rawvideo`，像素格式 `yuv420p`
- 分辨率要求：
   - `width % 32 == 0 && height % 32 == 0`
   - 建议帧内使用 `32×32` luma block 网格作为基本单位
- 从 FFmpeg pipe 读取时，必须视为紧密排列（Y 平面 `stride=width`），并且每帧字节数必须精确等于 `width * height * 3 / 2`；否则立即拒绝
- 若输入不是 FFmpeg pipe（例如外部 API），才允许进入“显式 stride 模式”；该模式必须走单独接口/代码路径（避免与 pipe 模式混用）

### 5.2 坐标系统（固定）
- FFmpeg pipe 模式下：Y 平面按行主序存储，`stride == width`（无 padding）为硬约束
- 外部 API 的显式 stride 模式下：stride 参数必须显式传入并与采样/地址计算全链路一致；不得复用 pipe 模式实现的隐含 `stride=width` 假设
- block 坐标：
   - block 大小：`32×32` 像素
   - block 网格：`Bx = width/32`，`By = height/32`
   - block 原点像素坐标：`(bx*32, by*32)`

### 5.3 帧内区域（固定但由生成器常量表给出）
`FRAME_LAYOUT_V1` 必须定义以下区域及其采样规则（全部为常量，不允许运行期改变）：

1) locator 区域
- 用于帧同步/粗定位（例如角标、模板匹配、或固定 pilot pattern）
- 生成器必须给出：
   - `LOCATOR_BLOCKS: [(bx,by)]`
   - locator 的采样点与判定规则（如阈值、相关/差分等）

2) pilots 区域
- 用于噪声/亮度归一化、质量指标 `Q_frame_norm` 估计
- 给出：
   - `PILOT_SAMPLES: [PixOff]`（直接为 Y 偏移，推荐）
   - 或给出 block+点位规则并可派生 PixOff
   - 统计方法必须确定性（i64 累加）

3) anchor 区域
- 每隔 `N_anchor_frames` 帧出现
- 给出：
   - anchor 的采样序列规则：`ANCHOR_SAMPLES: [PixOff]` 或等价规则
   - anchor block 重复规则：`R_anchor_blocks=8`（同帧重复 8 个 block 的采样位置集合）
   - 相关打分方法与汇聚顺序（见 10）

4) slots 区域（payload）
- 每帧固定 `slots_per_frame=24` 个槽位
- 每槽位固定承载 `B=4096` 个 coded bits
- 给出：
   - `SLOT_PIX_OFF_ALL[slot_id][4096]` 或
   - 给出一个“槽位内 bit→像素”规则 + 可派生 PixOff（推荐预派生避免热路径算坐标）
- r3f 推荐策略：
   - 生成器直接输出 `PIX_OFF_ALL[4096]` 表示“本槽位 coded bit j 对应像素偏移”（若 24 个槽位共享同一采样模式，则可共享；若不同，则必须按 slot_id 生成并固化为常量）
   - 若 24 槽位采样模式不同：则将 `PIX_OFF_ALL` 扩展为 `PIX_OFF_ALL[slots_per_frame][4096]`，并相应派生 `SYS/ PAR` 表（每槽位同一 route/π，PixOff 随 slot 变）
- 运行时实现建议在启动期固定选择“共享表路径”或“多表路径”，热路径不出现 `if slot_has_own_table`

> 实现注意：本规范后续以“每槽位存在一个 `PIX_OFF_ALL[4096]`”为默认描述；若你 24 槽位不同，按上述扩展维度处理，不改变语义。

## 6. 槽位 payload 结构与交织 π（强制）

### 6.1 逻辑结构（固定）
槽位 payload 的逻辑比特序列（交织前）恒定为：
- `payload_bits = SYS || PAR`
- 其中 `SYS` 长度 `B_sys`，`PAR` 长度 `B_par`，且 `B_sys+B_par=4096`

### 6.2 交织 π（强制）
- 槽位内 coded bit 的“提取顺序”是交织后的顺序（由生成器固定）
- 运行期实现必须语义等价于：先按 coded bit 序得到 `c[0..4095]`，再用 `π⁻¹` 还原到 `payload_bits` 顺序后，再做 Constant Split 写入 SYS/PAR
- r3f 最优实现不在热路径显式做 π⁻¹；而是通过派生表 `SYS_PIX_OFF/PAR_PIX_OFF` 把“π⁻¹ + split + route + 采样”合并到一次顺序写中（见 7）

## 7. demod LLR 与写入映射（r3f 最优正规形）

### 7.1 每帧 LUT（256-entry，i16）
每帧构建 `lut[256]`（i16），用于将 Y 像素映射为 LLR：
- 构建阶段允许 i32 中间计算
- 最终 clamp 到 ±`llr_sat`
- LUT 必须常驻结构体字段：`[i16;256]`，64B 对齐
- 热路径访问必须 0 bounds check：`get_unchecked(pix as usize)`
- `Q_frame_norm` 与 LUT 参数导出应复用同一遍 pilots 采样（不允许分别重复扫描同一批样本）
- pilots 统计遍历顺序必须固定（默认按 `PILOT_SAMPLES` 表顺序）；累计类型固定为 i64；舍入/缩放/clamp 顺序必须固定并版本化
- 推荐先固定一个 `PilotStatsV1`（如 `count/sum/sum_sq` 等最小统计元组），再由其导出 `Q_frame_norm` 与 LUT 参数；不同实现不得各自定义“等价但顺序不同”的统计口径

### 7.2 route_packed（回归/校验用）
`ROUTE_PACKED[4096]: u16`：
- `sel = (v >> 15) & 1`（0=sys,1=par）
- `off = v & 0x0FFF`（0..4095）
  约束：
- sys：off 必须覆盖 `[0..B_sys-1]` 恰好一次
- par：off 必须覆盖 `[0..B_par-1]` 恰好一次

### 7.3 从 route_packed 派生最终写入表（启动期一次；推荐生成器直接给出）
目标：得到最终热路径用的顺序写表：
- `SYS_PIX_OFF[B_sys]`
- `PAR_PIX_OFF[B_par]`

派生关系（语义）：
- 对每个 coded bit `j in 0..4095`：
   - `pix_off_j = PIX_OFF_ALL[j]`
   - `(sel, off) = ROUTE_PACKED[j]`
   - 若 `sel==0`：则该 coded bit 的 LLR 应写入 sys 目的位置 `off`
   - 若 `sel==1`：写入 par 目的位置 `off`
- 因为强制交织 π，`PIX_OFF_ALL[j]` 必须对应交织后的提取顺序；`ROUTE_PACKED` 也必须与该顺序一致（启动期校验）

因此可以直接构建：
- `SYS_PIX_OFF[off] = pix_off_j`（当 sel==0）
- `PAR_PIX_OFF[off] = pix_off_j`（当 sel==1）

校验：
- sys/off 全覆盖一次；par/off 全覆盖一次
- 若存在重复/遗漏：启动期拒绝（生成器 bug）

> 备注：如果你的实现把 π/π⁻¹ 与 route 的定义更复杂（例如 route 以 payload 顺序定义），那必须在生成器阶段统一到“提取顺序”的 `ROUTE_PACKED`，否则会引入运行期额外步骤并破坏最优正规形。

### 7.4 `pix_off` 顺序与访存局部性（生成器优化；语义不变）
- `SYS_PIX_OFF/PAR_PIX_OFF` 只要求对各自 `off` 域“一一覆盖”，不强制 `pix_off` 的空间顺序
- 生成器可在不改变 `off` 映射语义的前提下，尽量让 `pix_off` 顺序更具空间局部性（如按行块/小块聚类），以降低 `y_base` 随机访存延迟
- 可选扩展：生成器输出“分块后的 `pix_off` + 分块长度”，热路径按块处理以改善预取/向量化；必须通过回归验证 `off` 覆盖与写入语义完全一致
- 该类优化收益可能很高，但属于生成器策略优化：默认实现不强制，需基准与一致性回归共同守护
- 注意：若实现把 sys/par ring 的逻辑顺序固定解释为“按 `off` 线性写入后供 downstream 直接消费”，则不得重排 `off` 语义；此时只能优化 `pix_off` 的生成方式与局部性，而不能改变逻辑写入顺序

## 8. ring 结构、推进与最优写入循环（每槽位一次取模，最多两段连续写）

### 8.1 ring 形态（固定要求）
- sys ring 与 par ring 分开（与协议语义一致）
- ring 长度必须为 2 的幂：
   - `SYS_RING_LEN = 1<<k_sys`
   - `PAR_RING_LEN = 1<<k_par`
- mask：
   - `sys_mask = SYS_RING_LEN-1`
   - `par_mask = PAR_RING_LEN-1`
- ring 元素类型 `i16`，64B 对齐
- 运行期禁止“跨界指针递增后 wrap”（避免潜在 UB）；必须使用“两段连续写”正规形

### 8.2 写入位置推进（逻辑）
维护两个 64-bit 单调位置（元素单位）：
- `sys_pos: u64`
- `par_pos: u64`
  每处理 1 个槽位：
- `sys_pos += B_sys`
- `par_pos += B_par`
  擦除帧同样推进（语义是“逻辑空洞”，位置仍前进）

### 8.3 两段连续写正规形（必须）
对任意 ring、任意 `pos`、写入长度 `LEN`（B_sys 或 B_par）：

- 计算一次：`base = (pos as usize) & mask`（每槽位一次）
- 若 `base + LEN <= RING_LEN`：单段
   - dst = `ring_ptr.add(base)`
   - len = `LEN`
- 否则：两段
   - tail = `RING_LEN - base`
   - head = `LEN - tail`
   - 段1：dst = `ring_ptr.add(base)`, len = `tail`
   - 段2：dst = `ring_ptr.add(0)`,    len = `head`

段内：
- 允许 raw ptr 单调递增（始终 in-bounds）
- 允许 `get_unchecked_mut`/`get_unchecked` 消除 bounds check
- 禁止 per-element `&mask`

### 8.4 写循环模板化（必须）
必须用一个共享的内联函数（或宏）实现 sys/par 段写入，确保两边行为完全一致，避免分叉引入一致性 bug。

建议函数签名（Rust 概念）：
- `write_segment(dst_ring_ptr: *mut i16, ring_len: usize, mask: usize, pos: u64, pix_off: *const u32, len: usize, y_base: *const u8, lut: *const i16, erased: bool)`
  其中：
- `erased=true` 时按 8.5（默认不写 ring）；或在 `--materialize-erase` 时按两段 fill(0)
- 推荐再抽一层 `write_linear(dst, pix_off_ptr, n)`（内联），外层只负责计算 tail/head 并调用两次，以减少重复循环体代码与 I-cache 压力

### 8.5 擦除的写入策略（r3f 固定：默认不物化）
- 擦除 = 逻辑空洞，读侧当 0
- demod 热路径对擦除 span：
   - **跳过像素读取与 LUT**
   - **默认不写 ring**
   - 仍推进 `sys_pos/par_pos` 与 chunk 游标（O(1)）
- 读侧契约（强制）：
   - ingest/译码侧必须按 span 的 `is_erased` 分支处理；擦除 span 一律从零缓冲读取（或直接按 0 计算），**绝不可**从 ring 指针读取
   - ring 中旧值允许保留，但对读侧不可见
   - 推荐提供固定大小 `ZERO_LLR` 缓冲（例如 `ZERO_4096: [i16; 4096]`，或 `ZERO_LLR: [i16; MAX_SEG]` / 分块 4K/8K）复用
- 可选：`--materialize-erase`
   - 对 sys/par ring 对应两段范围 fill(0)
   - 仅在读侧复杂度/性能经基准证明确实受益时考虑；必须通过一致性回归 + 性能基准守护；否则不得默认开启

## 9. 门控与擦除（帧级两态；擦除=逻辑空洞）

### 9.1 质量指标 `Q_frame_norm`（固定口径）
- 由 pilots 区域统计得到（FRAME_LAYOUT 定义样本集合）
- 统计建议：
   - 用 i64 累加（确定性）
   - 输出为 Q 格式或整数范围（由生成器固定转换规则）
- `Q_frame_norm` 的统计口径、舍入规则、clamp 顺序必须与 7.1 的 LUT 参数构建共享同一份 `PilotStats`（同一遍采样、同一顺序）
- locator/pilots/anchor 的统计默认禁止自动并行归约（例如 rayon）；若候选评分并行，归约必须固定顺序（见 14）
- 门控阈值为 profile 固定常量 `T_frame_drop(Q15)`：越低越宽松

### 9.2 两态规则（固定）
对每个接收帧：
- 若 `Q_frame_norm < T_frame_drop(profile)` → 擦除
- 否则 → 保留

### 9.3 擦除表示：帧区间 run-length（强制）
记录擦除帧区间（半开）：
- `erased_frame_ranges = [(f0,e0),(f1,e1),...]`，单调追加，相邻合并
  当第 `f_rx` 帧擦除：
- new = `[f_rx, f_rx+1)`
- 若 last.e == new.s：合并；否则追加
  写侧推进：
- `sys_pos += slots_per_frame * B_sys`
- `par_pos += slots_per_frame * B_par`
- `f_rx += 1`
- 可选调试辅助：维护只读 bitset 索引（frame/slot 级）用于断言、随机查询或构造测试；热路径仍以 span 迭代器为主，不得依赖 bitset 随机访存

### 9.4 读侧：span 迭代器（强制；无除法/取模）
译码 ingest 必须使用单调游标（不得用随机位图/随机访存擦除判定）：
状态：
- `erase_cursor`
- `f_read`
- `slots_left_in_frame`（初始 24）

接口：
- `next_span() -> (is_erased: bool, n_slots: u32)`
  语义：从当前位置开始，返回连续擦除/连续非擦除槽位数量。span 内不再做区间边界判断。

要求：
- 不使用除法/取模
- 推进顺序固定，保证确定性
- `is_erased=true` 的 span 必须走显式零路径（零缓冲或直接按 0 处理），不得读取 ring 中旧值
- 推荐提供固定大小 `ZERO_LLR` 缓冲供 ingest/译码复用；若 span 超过缓冲长度，按固定分块顺序处理

## 10. chunk 组织与游标推进（sys 槽位边界；擦除 O(1)）

### 10.1 sys 槽位累计定义 chunk 边界（固定）
- 每处理一个槽位（不论擦除/保留）都推进 chunk 相关游标一次
- chunk 边界：累计 sys 槽位达到 `N_sys_slots_per_chunk` 即进入下一个 chunk

### 10.2 r3f 推荐实现：倒计时 `slots_left_in_chunk`
维护：
- `slots_left_in_chunk: u32`（初始 = `N_sys_slots_per_chunk`）
  每完成一个槽位：
- `slots_left_in_chunk -= 1`
- 若 `==0`：
   - `slots_left_in_chunk = N_sys_slots_per_chunk`
   - `chunk_idx += 1`
   - session/window 推进（释放/译码/写回）按固定顺序执行

### 10.3 擦除帧批量推进 O(1)：advance24_table（强制）
对每个 profile 预建：
- `advance24_table[left] = { left_new, chunk_inc }`，其中 `left` 表示当前 `slots_left_in_chunk`（1..N）
  擦除整帧（24 槽位）发生时：
- `a = advance24_table[slots_left_in_chunk]`
- `slots_left_in_chunk = a.left_new`
- `chunk_idx += a.chunk_inc`
- session/window 处理 `chunk_inc` 次（固定顺序、确定性）

### 10.4 span 级批量推进（可选优化）
- 若 span 迭代器经常返回 `n_slots > 1`（尤其连续擦除 run 较长），可预建更通用的推进表以减少循环开销
- 示例：`advance_slots_table[left][k] -> { left_new, chunk_inc }`，其中 `k` 为一次推进的槽位数（可按实现限制在 `1..24` 或更大）
- 使用要求：
   - 表驱动结果必须与逐槽推进完全等价
   - session/window 的 `chunk_inc` 次处理顺序保持固定
   - 表大小与缓存占用需通过基准确认，避免得不偿失

### 10.5 推进状态机统一化（建议）
- 建议把 `sys_pos/par_pos`、`slots_left_in_chunk`、`chunk_idx`、擦除/非擦除 span 推进统一到一个状态机函数：
   - 输入：`n_slots` 与 `is_erased`
   - 输出：位置增量、`chunk_inc`、是否触发/触发几次 window 动作
- 目标：减少边界分叉与重复实现，使擦除/非擦除路径共享同一推进逻辑（仅数据写入行为不同）

## 11. 元数据策略（META 强化；语义不变）

- 前 `K_meta_chunks=8` 个 chunk 反复承载 META（固定长度）
- META 解析与最终 hash 校验由 session 层完成
- 协议无 CRC：最终正确性由文件 hash 判定

实现要求：
- META chunk 的增强策略固定（生成器与解码一致）
- 对同一输入，META 解析输出必须确定
- chunk 写回建议采用固定策略（例如 mmap 或单一大缓冲顺序 flush）并固定顺序写出
- 建议写回同时维护 streaming hash，避免最终再全文件二次扫描

## 12. FEC：Systematic QC-SC-RA（窗口软译码；Layered；R-only；syndrome 增量）

### 12.1 总体规则（固定）
- 码：Systematic QC-SC-RA
- 译码：滑窗 soft decode（chunk 维度），每 profile 建议窗口大小 `window_chunks_suggest`
- 早停：仅 syndrome
- 推荐默认早停实现：维护 `unsat_count`（未满足 check 数）；早停条件 `unsat_count == 0`
- 数值：LLR/消息均为 i16 饱和；中间 i32/i64；显式 clamp
- 调度：固定 layered（按 layer 递增；layer 内按 edge 线性顺序）
- **实现版本必须固定唯一的 check 更新算子规格**（例如 min-sum/normalized/offset 或其他），包括量化格式、舍入、饱和/clip 点位与查表规则；不同实现不得自行替换“等价近似”

### 12.2 数据存储（r3f 固定）
- 变量端常驻：`Lq[v] : i16`
- 每条边仅存 check→var：`R_old[e] : i16`（R-only）
- var→check 即时生成：`L_v2c = sat_i16(Lq[v] - R_old[e])`
- syndrome 建议表示：
   - 默认：`syndrome_bit[check]`（u8 或 bitset）+ `unsat_count: u32`
   - 兜底：bitset（如 `u64[]`）+ 固定顺序 OR 归约早停（见 12.5）
- 工程约束：`Lq`/`R_old` 以及 syndrome 存储若声明为“64B 对齐”，实现必须真正提供 64B 对齐分配；`Vec<i16>` 默认对齐不足，不能视为满足约束
- 对于“上界固定”的运行时容器（如 window 内队列、候选列表、擦除区间缓存），优先固定容量 ring/arena（或至少启动期 `with_capacity` 一次到位），避免热路径扩容抖动

### 12.3 Lq delta 更新公式（强制）
对每条边更新：
1) `L_v2c = sat_i16(Lq[v] - R_old[e])`
2) 使用 check 更新算子得到 `R_new`
3) `Lq[v] = sat_i16(Lq[v] + (R_new - R_old[e]))`
4) `R_old[e] = R_new`
   要求：
- 顺序严格固定（layered）
- 禁止并行更新同一 `Lq[v]`
- check 更新算子（不改变算法语义前提下）的实现优化建议：
   - abs/sign 计算优先无分支位运算实现，避免数据相关分支
   - 若采用 min-sum 家族，`min1/min2` 可做向量化 reduction，但必须与标量参考逐元素一致
   - 饱和/clip 的触发点必须固定，避免“等价重排”导致结果偏差
- 上述优化默认不强制；若启用，必须以标量参考逐元素回归与反汇编/基准共同守护

### 12.4 Z=128 索引规则（强制）
所有 modulo 128 必须用：
- `(z + shift) & 127`
- `(z - shift) & 127`
  禁止：
- `% 128`
- 分支修正
- `perm_shift[128][128]` 查表

### 12.5 syndrome（早停依据）
- syndrome 表示每个 check 的 parity（或等价）
- 推荐实现（默认）：
   - 维护 `syndrome_bit[check]`（u8 或 bitset）与 `unsat_count: u32`
   - 当某 check 被 toggle 时，必须根据 `0→1` / `1→0` 转换同步更新 `unsat_count`
   - 早停条件：`unsat_count == 0`
- 兜底实现（风险更低）：
   - syndrome 存 bitset（如 `u64[]`）
   - 早停用固定顺序字级 OR 归约判断是否全 0（保持确定性）
- 一致性要求：
   - `unsat_count` 路径与“全量 syndrome 扫描”结论必须一致
   - bitset OR 归约路径与逐 check 判定结论必须一致
- 调试保险丝（推荐）：在 debug/regression 模式下按固定频率（如每 N 次 iteration）执行一次 bitset OR 或全量 syndrome 核对，用于及时发现 toggle/映射错误

### 12.6 SoA + layer 连续布局（强制）
必须使用 SoA：
- `LAYER_EDGE_START[layer]..[layer+1]` 给出该 layer 的边区间
- `EDGE_VAR_IDX[e]`、`EDGE_SHIFT[e]`（或 `EDGE_SHIFT_PARAM[e]`）、`R_old[e]` 在该区间内连续
  要求：
- 这些数组 64B 对齐
- layer 内顺序访问，便于硬件预取
- `R_old / EDGE_VAR_IDX / EDGE_SHIFT / (可选) EDGE_CHECK_ID` 这组“同 index e 访问”的数组应按访问方向同向连续放置，并尽量处于同一工作集区域，减少跨页/TLB 压力
- `Lq` 建议独立放置并 64B 对齐，避免与边表混排

### 12.7 var 索引压缩（推荐，若可行则必须）
若 `VAR_COUNT < 65536`：
- `EDGE_VAR_IDX` 用 u16
  否则 u32
  生成器必须固定类型并在启动期校验，避免运行期分支。
- 同理，若启用 `EDGE_CHECK_ID` 且 `CHECK_COUNT < 65536`，应优先使用 `u16`；否则 `u32`
- `LAYER_EDGE_START` 默认使用 `u32`（通常足够）；若实现改用更宽类型，需说明必要性

### 12.8 syndrome 增量维护：推荐“硬判决翻转触发”
推荐实现（通常更快）：
- 维护 `hard[v] = (Lq[v] < 0)` 或符号位
- 每次 Lq delta 更新后比较 hard 是否翻转：
   - 若未变：不更新 syndrome
   - 若翻转：默认遍历该变量的邻接 check `VAR_CHECK_ID[VAR_CHECK_START[v]..VAR_CHECK_START[v+1])`（按升序、去重、确定性），对对应 check 的 parity toggle（XOR）；若维护 `unsat_count`，必须在同一步完成 `0↔1` 计数更新
      默认需要生成器提供：
- `VAR_CHECK_START` + `VAR_CHECK_ID`（邻接 check 表；确定性排序、去重）
- 可选：若还需要 edge id 做其他增量逻辑，再额外提供 `VAR_TO_EDGES + EDGE_CHECK_ID`
- 翻转检测实现可采用无分支符号位比较/XOR 形式；仅在翻转时进入邻接表扫描

一致性要求：
- 该增量法必须与“全量 syndrome 重算”一致（回归测试必须覆盖）

## 13. shift 表示与两段拼接（r3f 默认轻量表示）

默认表示（推荐）：
- `EDGE_SHIFT[E] : u8`，取值 `0..127`
- 热路径按无分支算术派生两段拼接参数（统一标量/SIMD，无需 `shift<64` 分支）：
   - `s = EDGE_SHIFT[e]`
   - `src0 = s`
   - `len0 = 128 - s`（允许用 wrapping/sub 或等价无分支写法；`s=0` 时得到 128）
   - `src1 = 0`
   - `len1 = s`

可选扩展（仅在确有需要时）：
- `Shift2Seg = { src0: u8, len0: u8, src1: u8, len1: u8 }`
- 仅当未来需要“非标准两段拼接”时保留；否则不建议为每条边存 4 字节结构体

`Shift2Seg` 语义（对长度 128 的向量 `x[0..127]` 做循环移位得到 `y`）：
- `y[0..len0) = x[src0 .. src0+len0)`
- `y[len0 .. len0+len1) = x[src1 .. src1+len1)`
- `len0+len1 == 128`
- 若某段长度为 0，允许 len=0

## 14. Anchor-ID（抗平台转码；硬规格；确定性决策）

### 14.1 Anchor 结构与出现频率
- 每隔 `N_anchor_frames=12` 帧写入 Anchor
- Anchor 携带 `anchor_id mod M_anchor (127)`
- Anchor 序列长度 `L_anchor=127`
- 同帧重复 `R_anchor_blocks=8` 个 block（增强相关）

### 14.2 相关打分（固定口径）
- 输入：从 anchor 区域采样得到的序列（u8 或映射到 ±1）
- 与 `ANCHOR_SEQ` 做相关/点积得到分数
- 若实现尝试“两阶段（粗筛→精算）”加速候选搜索，粗筛必须是可证明上界剪枝；否则不得作为默认路径
- 多 block 汇聚规则（固定确定性）：
   1) 先计算 8 个 block 的独立分数 `s0..s7`（允许并行）
   2) 再按固定顺序相加：`S = (((((s0+s1)+s2)+s3)+s4)+s5)+s6+s7`
      禁止并行归约导致不确定；实现时避免使用会改变加法顺序的自动向量归约
- 候选评分若并行执行，必须先写入 `score[candidate]` 数组，再由单线程按固定顺序扫描做 argmax + tie-break；禁止线程直接竞争共享 `best`

### 14.3 命中与 margin（固定阈值）
- `S >= T_anchor_hit` 才认为命中候选
- top-1 与 top-2 的差 `>= T_anchor_margin` 才认为可信

### 14.4 校准规则（确定性）
- 结合顺序时基与 `anchor_id` 推导时间偏移（插删帧/剪切/重封装容错）
- 允许的最大跳变 `K_anchor_jump_max=8`，超过则不校准

### 14.5 tie-break（强制）
当分数或 margin 出现相等边界时，必须采用确定性规则：
- 分数更大者胜
- 分数相等：候选 `anchor_id`（或候选索引）更小者胜
- margin 相等也按同一 id 规则决胜

### 14.6 `--anchor-prune`（可选，默认关闭）
- 只允许在“可证明不改变 argmax”的条件下启用
- debug 构建必须带断言/校验：任何被剪枝候选都必须满足“其上界不可能超过当前 best”
- 回归必须覆盖：剪枝开/关 argmax 一致；最终 hash 一致
- 推荐提供固定种子的 fuzz 回归（随机帧噪声、随机候选集合）

## 16. FFmpeg I/O 规范（强制）

- 解码端只读 FFmpeg 解压后的 rawvideo（YUV420p）
- 编码端只写 rawvideo（YUV420p）再交 FFmpeg 压缩封装
- 核心不解析容器，不处理编码格式差异；所有容器/编码问题交给 FFmpeg
- 从 FFmpeg pipe 读取 rawvideo 时，必须按固定帧长 `width*height*3/2` 分帧；短读/长读/非整帧均视为输入错误并拒绝
- FFmpeg pipe 模式不得引入自定义 stride；stride 约束见 5.1/5.2

实现建议：
- 通过 `ffmpeg -i input -f rawvideo -pix_fmt yuv420p pipe:1` 管道输入
- 输出同理：`-f rawvideo -pix_fmt yuv420p`
- 读取实现应等价于 `read_exact(frame_bytes)`：每帧必须读满固定字节数，不足即 EOF/错误
- 输入侧建议使用大块读取与缓冲复用（例如一次读取多帧或至少 >1MB 级别缓冲），减少系统调用
- 帧缓冲建议单缓冲/双缓冲复用，避免每帧分配与重复拷贝

## 17. x86 / AVX2 / AVX-512 实现硬约束（Rust 优先）

1) 热数组 64B 对齐：ring、LUT、pix_off、消息数组、syndrome、擦除区间表头部、QC 表
   - 工程实现必须真正满足 64B 对齐（如 `#[repr(align(64))]` 包装或显式对齐分配）；不能把 `Vec<i16>` 默认对齐当作满足条件
   - 建议在启动期或单测断言关键缓冲区指针满足 `addr % 64 == 0`
2) LLR i16；核心算子饱和算术（SIMD 或标量等价）
3) Anchor 点积：
   - 有 VNNI 优先
   - 否则 AVX2 `maddubs` 组合
   - 再不行标量
4) 同输入同输出：统计 i64 累加；禁止非确定性并行归约
5) Z=128：索引用 `&127`；shift 两段拼接；热路径无 `shift<64` 分支
6) 窗口内存回收：固定清零点（分块清零/代际清零均可），清零触发点固定以保证确定性
   - 推荐优先代际清零（generation）：在固定触发点（建议 chunk 边界/window 推进）bump generation，首次访问时按需初始化
   - 若不使用代际清零，也应优先按 layer/窗口滑出区段做分段清零，避免每次全量 memset
7) Rust 溢出：中间 i32/i64；显式 clamp；禁止依赖 debug/release 差异
8) SIMD dispatch：启动时一次 `is_x86_feature_detected!`，运行期路径固定
   - 同理建议 profile dispatch 也在启动期固定（函数指针/单态化入口），避免热路径 `match/if`
   - 其他热路径开关（如 `unsat_count`/syndrome 早停实现、`materialize-erase`）也建议在启动期固定为函数指针或等价分派
9) demod→ring：必须使用“两段连续写正规形”，禁止 per-element &mask，段内 0 bounds check
10) `unsafe` 使用应集中封装在少数函数中，并与启动期 hard fail 校验绑定；只有在不变量已验证后才允许使用 `assume`/省略检查
11) 建议使用 const 泛型/newtype 固定常量长度（如 `Lut256`、`PixOff4096`、`SysPixOff<const BS: usize>`），减少越界风险与热路径隐式 bounds check 空间
12) 能从 profile/分辨率推导的量（如 `frame_bytes`、`y_plane_len`、`chunk_bits/chunk_bytes`、mask/len）应在启动期缓存到结构体字段，热路径不重复计算

## 19. 测试与回归（最小充分集 + r3f 必须项）

### 19.1 端到端一致性（必须）
- 同输入、多次运行：最终 hash 一致
- 不同 SIMD 路径（标量/AVX2/AVX-512）：最终 hash 一致
- `release` 最小集 vs `debug/regression` 扩展集：最终 hash 一致
- 开关矩阵：
   - 默认路径 vs `--no-route-seqwrite --no-pix-off` 回退路径：hash 一致
   - `--anchor-prune` 开/关：argmax 一致；hash 一致
   - `--materialize-erase` 开/关：hash 一致

### 19.2 demod→ring 回归（必须）
- 热路径约束：
   - 非擦除写循环：无 per-element mask、无 bounds check（建议 CI 加 `objdump/cargo asm` 检查，或以 microbench 阈值守护）
   - 建议工程化：对关键函数做符号级反汇编检查，防止循环体重新引入 `&mask` 或边界检查分支
- LUT unsafe 回归：
   - 随机像素帧 + 随机 profile + 随机擦除模式，比较 debug_route 路径逐元素一致（或 hash 一致）
- 擦除等价：
   - “逻辑空洞不写 ring + 读侧当 0” vs “物化写 0” hash 一致
- 擦除读侧契约：
   - `is_erased` span 必须走零缓冲/零路径；构造“ring 中残留脏值”场景验证结果仍一致

### 19.3 擦除 span/游标（必须）
- frame run-length 合并正确
- span 边界（跨 range、跨帧、跨槽）读取值一致
- 不允许除法/取模（可通过静态审计/基准热点确认）
- 若启用 `advance_slots_table` 等 span 级查表推进：必须验证与逐槽推进完全一致（含 `chunk_inc` 次 session/window 调用顺序）

### 19.4 QC 回归（必须）
- `sat_i16`：标量参考 vs SIMD 逐元素一致；覆盖 ±llr_sat 边界与随机长序列
- Z=128 索引：`&127` 与 `%128` 参考一致（启动期/单测）
- R-only 正确性：与“存全边消息”的参考实现 hash 一致（至少在测试集）
- check 更新算子：必须有固定标量参考实现与测试向量；优化实现（无分支/SIMD）需逐元素对齐
- syndrome 增量：
   - 与全量 syndrome 重算一致
   - 若使用 hard-bit 翻转触发：必须覆盖翻转/不翻转两类路径
   - 若使用 `VAR_CHECK_START/VAR_CHECK_ID`：覆盖邻接表有序/去重校验与越界拒绝
- syndrome 早停实现：
   - 若使用 `unsat_count`：覆盖 toggle 导致 `0→1` 与 `1→0` 的计数更新正确性，并与“全量扫描是否全 0”一致
   - 若使用 bitset OR 归约：与逐 check 扫描早停结论一致
- check 更新算子优化（若启用）：
   - 无分支/向量化实现与标量参考逐元素一致（覆盖边界值与随机序列）
- LUT/Q_frame_norm 构建：固定采样集合与顺序、纯整数路径、舍入规则与 clamp 顺序需有回归样例覆盖（避免不同实现隐性分歧）

### 19.5 Anchor 回归（必须）
- tie-break 边界用例：分数相等/margin 边界时选择确定
- `--anchor-prune`：剪枝断言（debug）不触发；且与全搜一致

### 19.6 性能回归（建议强制）
- microbench：demod→ring 吞吐（LLR/s、cycles/LLR）
- perf counters（可选）：L1 miss、store throughput、branch miss
- 约束：默认路径不得退化超过固定阈值（由你们团队设定）
- 手工 unroll（4/8）与预取（prefetch）属于中风险微调：默认实现不强制；若启用，必须以 microbench + 反汇编检查共同守护
- QC 热路径优化（如 `unsat_count`、bitset syndrome、check 更新向量化、代际清零）同样必须用 microbench 守护，并记录测试配置（window 大小/profile/SIMD 路径）
- demod→ring 的 SIMD gather/非 gather 路径不得先验假设更快；必须按实际 `pix_off` 分布做 microbench 决策

## 20. 参考伪代码（关键热路径）

### 20.1 两段连续写：非擦除段
```rust
#[inline(always)]
unsafe fn write_segment_non_erased(
    ring: *mut i16,
    ring_len: usize,
    mask: usize,
    pos: u64,
    pix_off: *const u32, // len = LEN
    len: usize,
    y_base: *const u8,
    lut: *const i16,     // [256]
) {
    let base = (pos as usize) & mask;
    if base + len <= ring_len {
        let mut dst = ring.add(base);
        let mut p = pix_off;
        for _ in 0..len {
            let off = *p as usize;
            let pix = *y_base.add(off) as usize;
            let llr = *lut.add(pix);
            *dst = llr;
            dst = dst.add(1);
            p = p.add(1);
        }
    } else {
        let tail = ring_len - base;
        let head = len - tail;

        // tail
        {
            let mut dst = ring.add(base);
            let mut p = pix_off;
            for _ in 0..tail {
                let off = *p as usize;
                let pix = *y_base.add(off) as usize;
                let llr = *lut.add(pix);
                *dst = llr;
                dst = dst.add(1);
                p = p.add(1);
            }
        }
        // head
        {
            let mut dst = ring;
            let mut p = pix_off.add(tail);
            for _ in 0..head {
                let off = *p as usize;
                let pix = *y_base.add(off) as usize;
                let llr = *lut.add(pix);
                *dst = llr;
                dst = dst.add(1);
                p = p.add(1);
            }
        }
    }
}
```

## 22. 协议最简声明（对外）

- 帧内只有 locator/pilots/anchor/slots（固定位置与规则，由 FRAME_LAYOUT 常量定义）
- 每槽位 payload 固定长度 `B=4096`，逻辑结构恒定 `[B_sys|B_par]`，强制槽位内交织 `π`（profile 固化）
- 无帧内编号字段；落位基于顺序时基与 Anchor-ID 校准
- 门控为帧级两态擦除（擦除=逻辑空洞，LLR=0）；统一窗口软译码；最终以文件 hash 判定正确性
- 所有容器与压缩/解压由 FFmpeg 完成；核心只处理 raw YUV420p
