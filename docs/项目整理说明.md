# File2VideoEncoder vNext-7 架构说明（全面收敛版）
**Headerless 顺序时基 + 固定槽位 + 隐式索引 + 两态门控（擦除化） + Systematic QC-SC-RA（平稳流式窗口软译码） + 槽位内恒定 sys/par 分割（Constant Split） + 元数据源前缀强化（去 Bootstrap / 去模式切换 / 去位级调度器）**

本版本在 vNext-6（Systematic QC-SC-RA + 固定周期 sys/par 复用 + 平稳穿孔 + 极小帧头）基础上继续做“架构级收敛”，目标是把系统进一步压到更少机制、更规整的流水线，同时不牺牲信道利用率、可靠性与吞吐。

核心变化：
- 删除 **Frame Header** 整条控制面译码链（不再解 frame_no / stream_id / profile_id）
- 删除 **位级 sys/par 周期复用 + puncturing 掩码调度器**
- 改为 **顺序时基（Headerless）** + **槽位内恒定 sys/par 分割（Constant Split）**
- 保持对外协议极简：仍只有一种载荷——固定长度 coded bit chunk；无 packet/symbol/generation/seed/degree/crc；无阶段切换点

输出仍被定义为由 profile 完全固定的 **平稳无限码流**，只是在映射层从“位级周期表”收敛为“槽位内固定结构”。

---

## 0. 一句话总结
把“帧头解码→拿 frame_no→才能落位”的单点依赖删掉，把“sys/par 周期复用 + 穿孔”的位级调度删掉，改为：

**LLR → 单一平稳流式 Systematic QC-SC-RA 窗口软译码 → 输出源块**  
并用 **顺序时基** 作为全局索引，用 **槽位内恒定 sys/par 分割** 作为 rate/早期可用性的唯一表达（仍然零信令、零切换点）。

---

## 1. 设计目标与约束

### 1.1 目标
1) 架构极简  
- 系统只有一种载荷：固定长度 **coded bit chunk（槽位 payload）**  
- 协议层不出现 packet/symbol/generation/seed/degree/crc  
- 删除引导区/阶段切换：整条码流从头到尾结构恒定

2) 极致性能  
- 解调直接产出 bit LLR，直入统一译码器（BP/Min-Sum / layered）  
- **窗口译码**固定工作集，内存上界可控，吞吐稳定  
- 槽位并行：每槽位独立提取 LLR（SIMD/多线程）  
- 编码器为 **RA**：重复 + 互连/延时 + 累加器，线性时间、规整流水

3) 高可靠性  
- **两态门控**：低置信槽位直接 LLR=0（擦除），避免坏软信息污染稀疏图  
- 最终全文件 hash 校验；可选“分块 CRC”仅用于早停/定位（不进入协议）

4) 信道利用率不降  
- 删除帧头区域、per-slot CRC、外码头、组合描述字段  
- 控制面仅保留：locator/pilots（物理同步/标定必需）

### 1.2 约束（沿用）
- YUV420p，优先 Y 平面承载  
- 32×32 luma block 网格，`width % 32 == 0 && height % 32 == 0`  
- 几何模型轻量（平移 + 轴向缩放），可选 heavy 搜索路径  
- 不提供抗篡改认证（可扩展但不在本次范围）

## 2. 总体分层（最简 4 层，且更规整）

1) `phy+channel/`  
帧布局（locator/pilots/slots）、调制/解调、几何估计、噪声估计与 LLR 归一化 → 逐槽位 LLR + 槽位质量 Q

2) `mapper/`（新，极薄）  
**顺序时基** + **槽位内恒定 sys/par 分割** → 把每槽位 LLR 写入系统流/校验流的连续区间

3) `fec/`  
统一前向纠错：**Systematic QC-SC-RA**（平稳流式窗口软译码）

4) `session/`  
输出重组、块写回、最终 hash 校验、窗口滑动与资源回收

删除：`frame_header/`、`symbol/`、`fec_inner/`、`fec_outer/`、`bootstrap/`、`syspar_scheduler/`、`puncture_masker/`。

---

## 3. 统一帧型（进一步简化：只有 locator/pilots/slots）

### 3.1 栅格与对齐
- `Y_BLOCK = 32` 划分 luma block 网格  
- `MARGIN_BLOCKS` 可保留 1（防边缘压缩/采样误差）

### 3.2 每帧固定区域
A) Locators：四角定位块（方向判定 + 粗几何）  
B) Pilots：稀疏已知符号块（每帧标定均值/噪声/极性/单调性）  
C) Slots：固定数量槽位，承载固定长度 payload（经调制落像素）

关键点：  
- 无 frame header；任何帧只要能同步就能产出槽位 LLR  
- 同步失败的帧视为“整帧擦除”（或按实现细化），但不会造成索引解耦失败

---

## 4. 时间索引与隐式寻址（Headerless 顺序时基）

### 4.1 顺序时基定义
定义全局槽位计数器 `t = 0,1,2,...` 为“接收端处理到的第 t 个槽位”。  
编码端同样按输出顺序定义 `t`，两端一致无需任何帧内编号字段。

- 编码端：写出槽位即 `t++`  
- 解码端：从视频流中读到一帧，若几何同步成功，则按固定 slot 顺序依次产出槽位 LLR，并 `t++`；若该帧同步失败，则该帧所有槽位视为擦除，但 `t` 仍然按槽位数前进（等价“缺测”）。

### 4.2 为什么这仍然可靠
- 原先“必须先解 frame_no 才能落位”的单点依赖被消除  
- 坏帧退化为普通擦除，交给 SC-RA + 门控处理  
- 索引逻辑只剩一个单调递增计数器（最小状态机）

> 取舍：此方案默认不支持“从视频中间任意位置随机起播且无需外部信息即可直接落位”。若需要随机起播/剪切恢复，可选“同步锚点帧”（见第 18 节）。

## 5. 槽位 payload 的恒定结构（Constant Split）

每个槽位承载固定总比特数 `B`（profile 固定），并**恒定分割**为两段：

- 系统段：`B_sys` bits  
- 校验段：`B_par` bits  
且 `B_sys + B_par = B`。

槽位 payload（发送端）：
`payload(t) = SYS[t] || PAR[t]`
其中：
- `SYS[t] = S_sys[ t*B_sys : t*B_sys + B_sys )`
- `PAR[t] = S_par[ t*B_par : t*B_par + B_par )`

接收端落位（写入 LLR）：
- 将槽位系统段 LLR 写到 `S_sys` 对应区间  
- 将槽位校验段 LLR 写到 `S_par` 对应区间  
- 若门控丢弃该槽位，则两段 LLR 全置 0（擦除）

收益：
- 删除“位级 sys/par 周期 pattern”与“puncture mask”的所有对齐/调度复杂度  
- 映射变成两个乘法+两段连续拷贝（极简、极高吞吐）  
- 仍然严格平稳：每个槽位结构永远相同

不同码率（或鲁棒性）表达方式：
- 通过不同 profile 选择不同的 `(B_sys, B_par)` 比例  
- 不再通过 puncturing 调参（避免位级掩码器）

## 6. 两态门控（擦除化，继续替代 per-slot CRC）

per-slot CRC 的核心价值是“坏槽位强制擦除化”。本架构继续用门控承担此抽象，但因为槽位结构恒定，门控更单一、更干净。

### 6.1 质量评分 Q（最小充分集）
每槽位输出：
- `Q_pilot`：pilots 一致性（残差与噪声估计一致、极性/单调性检查）

推荐最简门控输入：
- `Q = Q_pilot`

### 6.2 门控规则（两态）
- 若 `Q < T_drop`：该槽位的 **sys 段与 par 段 LLR 全置 0**（擦除）  
- 否则：正常使用（LLR 由噪声方差归一化后直入译码器）

策略建议：宁可擦除也不喂坏 LLR（保守优先）。

---

## 7. 元数据策略（保持平稳，去 Bootstrap）

继续采用最简单且工程稳定的方案：

### 7.1 方案 A：元数据源前缀强化（默认）
- 源比特流：`META || DATA`  
- 将 `META` 重复 `r_meta` 次后再接 `DATA`：  
  `SRC = repeat(META, r_meta) || DATA`

特点：
- 实现最简单  
- 对长文件均摊开销极小  
- 因为槽位系统段持续出现，META 的收敛通常更早、更稳定

（可选）方案 B：元数据回声（保持严格平稳的永久 beacon）  
如果希望“超短文件也能很快拿到 META”且不在乎永久占用极小比例，可在系统流里按固定周期插入 meta 位，但默认不建议增加常驻机制。

---

## 8. 统一 FEC：Systematic QC-SC-RA（窗口软译码）

### 8.1 结构保持不变，但输出接口更简单
FEC 内部维护两条逻辑子流：
- `S_sys(i)`：系统位子流（源信息）  
- `S_par(i)`：校验位子流（RA + SC + QC 结构生成）

对外不再做任何位级复用/穿孔：复用由“槽位内恒定分割”完成。

### 8.2 profile 固定内容（协议零开销）
- QC lifting 因子 `Z` 与循环移位/延时表（或生成规则）  
- SC 耦合记忆 `m` 与耦合方式  
- 重复度 `q`（可选两度混合如 `{2,3}`，仍保持极简）  
- 窗口译码建议窗口长度（实现可调）  
- 约束：`B_sys`、`B_par` 推荐与 `Z` 对齐（见第 12 节）

### 8.3 译码
- 统一窗口化 BP/Min-Sum（可 layered）  
- 固定工作集：窗口内变量/校验节点、LLR ring buffer  
- 块收敛后立即写回输出并释放状态（吞吐稳定）

---

## 9. 无限码流视角（对外仍是一条“平稳无限流”）

为了保持你原先的“对外只有一种载荷、零信令”的表达方式，这里给出等价描述：

- 对外仍可以把系统定义为一条平稳无限码流 `S(t)`，每槽位承载 `B` bits  
- 但内部实现用 `S_sys` 与 `S_par` 两个连续子流，槽位 payload 是二者的恒定拼接  
- “码率”由 `(B_sys, B_par)` 的固定比例决定，属于 profile

---

## 10. 编码流程（端到端）

1) 参数校验（分辨率、profile）  
2) 读取文件 → 切块 `chunk_bytes=C_profile` → 计算最终 hash  
3) 生成元数据块 `META`（占用若干源块）  
4) 源侧组织：`SRC = repeat(META, r_meta) || DATA`  
5) 初始化 Systematic QC-SC-RA 流式编码器（结构由 profile 固定）  
6) 初始化全局槽位计数器 `t=0`  
7) 对每帧：
   - 写 locators + pilots  
   - 对每个槽位（固定顺序）：
     - 取系统段：`SYS = S_sys[t*B_sys : t*B_sys + B_sys)`  
     - 取校验段：`PAR = S_par[t*B_par : t*B_par + B_par)`  
     - 拼接并调制写入槽位：`payload = SYS || PAR`  
     - `t++`
8) 输出 YUV 或 pipe 给 ffmpeg/x264

停止条件：
- 有限视频：发到 `max_overhead` 或 `max_frames` 即停止  
- 广播模式：持续发（无限冗余，直到用户停止）

---

## 11. 解码流程（端到端）

1) 读取视频帧（rawvideo）  
2) 初始化全局槽位计数器 `t=0`  
3) 每帧：
   - 几何估计（快速/ heavy）  
   - pilots 标定 → 噪声估计与 LLR 归一化参数  
   - 若该帧同步失败：将该帧所有槽位视为擦除（等价全 LLR=0），并令 `t += slots_per_frame`，继续下一帧  
   - 若同步成功：对每槽位（并行）：
     - 计算 `Q`，门控：若不可信则该槽位两段 LLR 全置 0  
     - 否则提取槽位 payload 的 bit LLR  
     - 将前 `B_sys` 写入 `S_sys` 对应区间，将后 `B_par` 写入 `S_par` 对应区间  
     - `t++`
4) 统一译码器窗口迭代：
   - 在窗口内对 Systematic QC-SC-RA 做 BP/Min-Sum（可 layered）  
   - 当某个源块 `u` 收敛（可选：块 CRC 通过）：
     - 立即写入输出文件对应位置  
     - 释放该块相关窗口状态
5) 元数据处理：
   - META 因前缀强化应更早收敛，尽早得到文件长度/hash  
6) 全部块完成后：
   - 计算输出 hash，与元数据 hash 比较  
   - 成功则输出文件；失败严格报错（可选 `--best-effort`）

---

## 12. 对齐与性能建议（让流水线更“硬”）

强烈建议：
- `B_sys` 与 `B_par` 都选择为 `k * Z`（常用 `k=1 或 2`）  
- 槽位 payload 对齐 QC 单元边界（两段都是连续块），减少边界处理  
- LLR 缓冲使用环形缓冲，sys/par 分开两块 ring（连续写入最友好）

## 13. Profile（更小、更可解释）

### 13.1 profile 固定内容（强绑定物理层与 FEC）
- PAM 阶数：2/4/8  
- locator/pilots 布局与密度  
- slots_per_frame 与槽位几何排布  
- `B`：coded_bits_per_slot  
- `B_sys`、`B_par`：槽位内恒定分割（决定码率与早期可用性）  
- `chunk_bytes = C_profile`（推荐固化，避免状态机）  
- 元数据策略：前缀强化 `r_meta`  
- FEC：Systematic QC-SC-RA 定义  
  - QC：`Z` 与移位/延时表  
  - SC：`m` 与耦合方式  
  - 重复度：`q`（或 `{2,3}`）  
  - 窗口建议：`window_chunks_suggest`

### 13.2 运行时参数（尽量少）
- `max_overhead`（有限视频）  
- `window_chunks`（解码端）  
- `--heavy-geom`、`--best-effort`

- `encode`: file → yuv/mp4

建议参数：

删除：

- per-slot crc 相关参数

## 15. 测试建议（重构后最小充分集）

1) 同步回归  
- locators/pilots 同步成功率曲线  
- 同步失败时是否正确按整帧擦除推进 `t`

2) LLR 统计回归  
- 无噪声、受控噪声下 LLR 分布、归一化一致性  
- sys/par 两段写入是否严格连续、无错位

3) 门控回归  
- 注入几何错位/标定异常，确认门控能把坏槽位两段全擦除，不污染译码  
- 阈值保守性：宁可擦除也不喂坏 LLR

4) FEC 单元测试（纯内存）  
- 随机源块 → 编码 → 随机擦除/加性噪声（LLR）→ 译码恢复  
- 覆盖 burst 擦除、不同 overhead、不同窗口大小  
- 覆盖不同 `(B_sys,B_par)` 比例下的收敛速度与误码门槛

5) 端到端无压缩  
- encode→decode 一致性（hash）

6) 端到端有压缩  
- x264 不同 CRF/preset 成功率曲线与吞吐  
- 重点关注：META 收敛帧数分布（应显著早于数据主体）

## 16. 迁移实施路线（最低风险）

1) 保留 `phy+channel` 不动：仍输出逐槽位 LLR + Q  
2) 新增 `mapper/`：实现顺序时基 `t` 与 constant split 写入 `S_sys`/`S_par` 两个 ring buffer  
3) FEC 侧把输入接口改为从 `S_sys`/`S_par` 两个连续流取 LLR（删掉旧的 pattern/puncture 逻辑）  
4) 上线两态门控（先保守阈值）  
5) 上线元数据前缀强化（默认 r_meta）  
6) 删除旧 frame header、syspar scheduler、puncture masker、以及所有相关参数

---

## 17. 关键取舍说明（为什么这是“更优的架构收敛点”）

- vNext-6 的主要剩余复杂度来自两块：  
  1) 帧头解码链（强保护小码 + 重复合并 + 判决 + 失败分支）且与落位强耦合  
  2) 位级 sys/par 复用 + puncturing 调度器（对齐、跨槽位边界、窗口边界复杂）

- vNext-7 把两块都删掉：  
  - 用顺序时基替代显式 frame_no：坏帧退化为擦除，不再“拿不到 frame_no 就无法落位”  
  - 用槽位内恒定分割替代位级调度：映射只剩两段连续写入，极致规整与吞吐

- 信道利用率不降：  
  - 省掉帧头区域，净载荷只会更高  
  - 若想保持与旧版完全相同的占比，可把省下区域用于更密 pilots 或更保守调制（换鲁棒性）

---

## 18. 可选扩展：同步锚点帧（仅当你需要“随机起播/剪切恢复”）

默认 Headerless 顺序时基不保证“从任意中间帧开始就能直接落位”。若你必须支持此能力，可增加**唯一**一个可选机制，仍保持“无字段”的风格：

- 设定固定周期 `N_anchor`（profile 固定）  
- 每隔 `N_anchor` 帧，把 pilots 区中的一个极小子区域替换为强相关序列（或相位编码序列）  
- 接收端通过相关峰恢复锚点位置，从而重建绝对时基（或至少重建到最近锚点的偏移）

该机制不引入 frame header 字段，不引入多阶段协议；只是在 pilots 内做“固定周期的可检测结构”，实现成本低且可选。

---

## 19. 默认参数建议（可直接落地的起点）

- profile：PAM4（折中）+ pilots 稍密（标定稳）  
- `chunk_bytes = 16384`（固化进 profile）  
- `window_chunks = 256`（约 4MB 源数据窗口）  
- `max_overhead = 0.20`（有限视频）  
- 元数据前缀强化：`r_meta = 4`（起点：2~6 调）  
- constant split：选择 `B_sys:B_par` 比例作为主要“码率/鲁棒性旋钮”  
  - 例如更鲁棒：降低 `B_sys`、提高 `B_par`  
  - 更高码率：提高 `B_sys`、降低 `B_par`  
- 门控阈值：宁可擦除也不喂坏 LLR（保守优先）

## 20. 对外协议最简声明（最终形态）

- 帧内只有 locator/pilots/slots（固定位置，固定尺寸）  
- 槽位 payload 永远是固定长度 `B`，且结构永远是 `[B_sys 系统段 | B_par 校验段]`  
- 全局索引由“顺序时基”定义，无任何帧内编号字段  
- 译码统一窗口化软译码，门控把坏槽位擦除化  
- 文件正确性以最终 hash 为准（必要时块 CRC 仅作内部早停/定位）

以上即 vNext-7：更少机制、更规整映射、更低实现复杂度，同时保持（甚至提升）净载荷与吞吐。
